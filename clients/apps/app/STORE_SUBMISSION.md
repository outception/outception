## Build and submit

```bash
cd clients/apps/app
eas login
eas build --profile production --platform all
eas submit --profile production --platform ios
eas submit --profile production --platform android --key path/to/key.json
```

The first build creates credentials (Android keystore generated by EAS, iOS signing via the Apple account). `eas.json` sets the Android track.

The App Store Connect API key and the Sentry DSN are deliberately **not** in `eas.json` — it is committed to a public repository. Hold them in EAS instead, where they stay account-side:

```bash
eas credentials              # store the App Store Connect .p8, its key id and issuer id
eas env:create --name EXPO_PUBLIC_SENTRY_DSN --scope project
```

`eas submit` then reads the key from EAS rather than from a path in the checkout.
